# Agent instructions

Before changing the popup or other user-facing interface, read [DESIGN.md](DESIGN.md) and follow its tokens, hierarchy, interaction language, accessibility requirements, and privacy constraints. Keep product behavior and claims consistent with [PRODUCT.md](PRODUCT.md).

Preserve the local-first model. Microsoft personal Bookings is published availability, not a full calendar or Shared Bookings integration. Optional Google OAuth checks only primary-calendar free/busy; never claim it was verified live without account evidence. Do not imply access to Microsoft Graph or event details. Keep skip non-punitive, reminders calm, and exercise guidance comfortable and optional. Update the design guide when an approved UI change establishes a durable visual or interaction rule.

Manual Start early / Start now must consume one of today's planned snacks and clear its alarm without checking the calendar or duplicating credit. Preserve active-session exclusivity. Calendar failure, missing/stale availability, work hours and the reminder toggle must not gate a manual start; calendar-based reminders still need verified availability. When no calendar is configured, a check fails, or there are insufficient free gaps, fill the remaining daily budget with evenly spaced, explicitly labeled time-based reminders inside weekday work hours. Never present those as verified free slots or manufacture a calendar snapshot. Keep calendar errors visible, the one-hour spacing and daily budget, and a quiet calendar-setup CTA on Today. Camera Coach belongs in a dedicated visible tab and requires explicit per-session camera opt-in. Bundle model/WASM/code locally; never record, upload or persist frames or landmark sequences, and always stop camera tracks on pause/end/target/tab-hide/navigation. Store summary counts only, preserve manual/timer alternatives, and label automatic squat counts experimental rather than verified form. Do not claim real-person accuracy/performance targets without the required human webcam evaluation.

Use MediaPipe world landmarks for 3D knee angles and normalized image landmarks for framing/hip descent. Keep the recorded-squat regression (`npm run test:camera`) passing through the built extension's actual camera/model/counter path without manual additions; synthetic landmark tests alone do not prove motion counting.

For explicitly authorized offline recording tests only, save private representative frames, annotations and body-pose traces under the ignored `.private-camera-fixtures` directory, never in tracked sources, releases, screenshots or attachments. Preserve Vite's denial of this directory and `.camera-cache`. The production camera must still persist summaries only. Default tests must explicitly skip an absent private fixture; `test:camera:private` must fail when requested fixtures are missing. Review expected counts visually, keep floor movements as negative squat cases, and verify changes through the actual packaged camera/model/UI path as well as deterministic pose replay.

Forward torso lean is not sufficient evidence of a floor exercise: use whole-body orientation and preserve the calibrated standing scale through foreshortening. Keep both private recording regressions when available; do not fix one person's counts by adding age-specific thresholds or weakening confidence/framing checks.
